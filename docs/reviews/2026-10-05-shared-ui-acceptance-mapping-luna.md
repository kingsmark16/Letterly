# Shared UI acceptance evidence map

**Reviewed by:** GPT-6 Luna  
**Baseline:** HEAD `ddf8a71`  
**Scope:** Read-only review of spec 0009 AC-1–AC-12, its verification checklist, the eleven named `@repo/ui` primitives, package exports and tests, direct production consumers, and existing browser/review evidence. This is an evidence map, not a source or spec change.

## Conclusion

Spec 0009 has strong evidence for canonical token/configuration ownership, source-owned primitive implementations, the landing tracer bullet, responsive layout at its documented viewport set, and several detailed component contracts. It is not ready for an overall acceptance declaration. The open checklist appropriately preserves larger claims whose evidence is either partial or not mapped across all consumers: comprehensive primitive/public-subpath compatibility, all retained CSS-module precedence, complete WCAG AA review, cross-surface behavior preservation, and art-direction parity.

The evidence timeline matters. Before this map, the broad three-engine UI run recorded 395 passes, 30 intentional credential skips, and one Firefox 1440 password-reset success failure. The unchanged case passed 20 isolated repetitions and the surrounding Firefox auth suite passed 32 enabled cases with ten skips, but the missing reset request had no established root cause. After this map, the complete fixture suite passed 444 cases with 30 intentional credential skips and no assertion failures. The current pass is additional regression evidence; it does not rewrite the earlier failure or establish that failure's root cause.

## Open verification checklist: evidence and residual checks

The current unchecked items in `verify.md` are compound claims. The evidence below can close named subclaims, but I do not recommend checking an aggregate box until its omitted cases are mapped.

1. **Primitive imports, props, attributes, and loading announcement placement.** `packages/ui/src/ui.test.tsx` directly verifies forwarded refs, native form values, `Button` variant/size/loading attributes, external loading status placement, `Field` relations, `Dialog` labels and lifecycle, and layout/status slots. Historical primitive migration reports preserve each component's before/after contracts. `shared-ui-public-exports.json` closes runtime resolution and named component availability for all eleven subpaths. Remaining limits are exhaustive prop-value/rendered behavior and a consumer map demonstrating where each historical contract is relied upon. The package's wildcard subpath export is the documented public contract.

2. **Production source scanning and emitted utility set.** `ui-configuration.test.ts` checks explicit app/source/package globs and test/spec exclusions. The subsequently added [production emission audit](2026-10-05-shared-ui-utility-emission.json) enumerates 141 static candidates from the eleven primitive owners and shared control styles and finds all 141 selectors in normal production CSS chunks. That is sufficient evidence that the enumerated candidate set is emitted at this revision. The audit does not prove browser application, winning cascade, or each conditional state; those belong to the separate computed-style and consumer checks below.

3. **CSS Module and computed precedence while old and new styling coexist.** Historical checks cover concrete cases such as the desktop editor target-size override, catalog Status styles, responsive landing Link compositions, and legal/preview Dialog layouts. The contrast correction removed the five `Input` border overrides that defeated the shared default. But `docs/reviews/2026-10-05-shared-ui-consumer-inventory.json` scopes itself to 52 direct JSX use sites in 15 files and explicitly is not a computed-cascade audit. Complete the open checkbox by mapping every `className`/`classNames` and any descendant CSS Module selector on a primitive to intended layout/appearance/state ownership, then record computed normal/hover/focus/disabled/loading/error output for every actual retained override. Do not interpret intentional `className` composition alone as a violation; the missing evidence is the comprehensive precedence map.

4. **Admin and every newly migrated surface compatibility.** Admin report/filter/confirmation/audit tests now cover shared controls, focus, target geometry, mutations and recovery; editor, preview, legal, public template, and landing checks also exercise actual callers. This closes those named examples. The checklist says “every newly migrated surface” and there is no exhaustive mapping from the current inventory to browser/test cases. A surface-to-test matrix is the missing artifact. The earlier password-reset failure remains unexplained historical evidence; the subsequent complete run passed, so the earlier event should not be presented as a failure of the current full run.

5. **Route/API/database/auth/privacy/rendering preservation.** Source ownership checks and individual migration reports support unchanged contracts for their own slices. To close the aggregate item, compare the current migrated-owner inventory against tests or explicit source-boundary evidence for each route/data/auth/privacy boundary; current representative checks cannot imply all flows. Keep the unexplained Firefox reset failure and its successful isolated repetitions separately reported.

6. **Secret Letter art and motion unchanged.** Existing public rendering, editor-media, template version, zoom, and motion journeys protect important template behavior; exact CSS-declaration cleanup evidence protects a separate set of unchanged declarations. Remaining evidence includes a specific before/current art-direction mapping for paper/envelope/flower/waveform and reduced-motion behavior across public/editor/preview callers. The current zoom run is Chromium/reduced-motion only, and screenshot review was explicitly not accepted in the zoom evidence. Keep this box open until those surfaces have direct coverage.

7. **Automated accessibility and manual checks.** Checklists and tests provide strong pieces: labels, errors, focus, forced colors on landing, actual Chromium 200% zoom on six fixture journeys, target geometry, reduced motion, and recent named contrast assertions. The checklist remains open for an automated accessibility check and manual review because the available evidence is not mapped across the in-scope shared controls and actual consumers. The contrast probe's opaque-background restriction and six-profile browser matrix describe its tested boundary; they do not create extra requirements for unsupported backgrounds or unreferenced compositions.

8. **Full production CSS/style/class-conflict/subpath/loading compatibility.** `cn` unit tests prove recognized caller utility conflicts; the export matrix proves all eleven canonical subpaths resolve; the emission audit proves the extracted 141 static candidate selectors appear in production CSS; and loading semantics are directly tested. There is still no complete computed-style/CSS Module precedence map for actual consumer compositions. The production performance gate is not a substitute for that contract check.

9. **All-surface performance.** The earlier landing-only baseline did not satisfy the surface budget. The newer artifact and test now cover 19 named production route/state scenarios at two widths, with route-specific historical comparisons; 38 performance cases are author-reported passing. That is sufficient to replace the earlier “landing only” gap for those 19 scenarios. The verify text remains broader (“each migrated surface”) than a fixed scenario list, so compare the 19 scenarios to the current direct/transitive consumer inventory before checking it. No general product-state or future-interaction budget claim follows.

### Production utility-emission audit update

After the initial map, `docs/reviews/2026-10-05-shared-ui-utility-emission.json` was added for this HEAD. Its source hashes match the eleven named primitive owners and `lib/control-styles.ts`. The embedded reproducibility script extracts static `className`/`cn` strings, `cva` base and variant values, and the five known class maps, then checks selector presence across normal production CSS chunks. It records 141 candidates, 12 CSS files, and zero missing selectors. `defaultVariants` choose values already represented in the corresponding variant map, so they introduce no distinct candidate strings. This closes the previously noted emission subclaim for the enumerated shared primitive source candidates at this revision.

The audit itself carefully limits its result: selector presence proves emission, not browser application, conditional-state behavior, or caller override precedence. It does not scan consumer-supplied classes/CSS modules or the separate `Code` helper. Thus it strengthens the production-output checkbox but does not close the separate consumer/cascade checkbox or prove each selector wins under its intended media/state conditions.

### Contrast coverage details

The current contrast test measures text contrast for three fixture Buttons, a base Input, an empty Textarea, an invalid Textarea, a label, description and error, plus the five real admin Input consumers. It measures keyboard focus contrast for the probed controls and normal/hover border contrast for the text controls. The artifact reports these as opaque-solid-background probes. This is useful evidence for the exact controls/states and routes named there.

It does not measure contrast for the `Link`, `IconButton`, `Card`, `Dialog`, or each `Status` state as a component; nor does it calculate hover/active text contrast for links/buttons, disabled/loading contrast, or alternate error/focus combinations. The next coverage pass should select actual consumer roles and applicable states from the primitive/consumer map, rather than add hypothetical combinations. Disabled controls may fall under the WCAG non-text contrast exception; record their state separately. Existing browser tests exercise function and focus behavior for some controls, but function tests are not contrast measurements. This does not indicate an observed AA failure; it identifies remaining named controls/states to reconcile with AC-3 and its checklist.
