# Sign in and sign up redesign

Both authentication routes now extend the landing page's dark burgundy and rose presentation. Desktop pairs a stationery illustration with a focused provider panel, engraved corners, and a small heart ornament. The illustration reuses the envelope and wax seal assets and has a finite entrance with a reduced motion fallback. Smaller screens center the provider panel. Short portrait and landscape screens remove optional supporting copy and adjust provider placement while retaining every action and error message. Browser metadata, session loading, and legal dialogs share the scoped dark palette.

Google and Facebook remain the only entry methods. Provider calls, safe callback and return paths, session redirects, retry behavior, and legal content are preserved. Both providers disable while a request is pending, the active provider exposes its busy state, and a status message announces progress. No dependencies, fonts, GPU effects, or authentication features were added. The old credential form styles and obsolete overlapping social layout overrides were replaced with the current page styles.

The ui-ux-pro-max design system search returned a generic marketing layout, so that result was not persisted. A focused editorial style search and accessible authentication guidance informed the composition, while the user's established burgundy art direction and existing Fraunces and Manrope fonts controlled the actual palette and typography.

Primary text on the panel measures 14.31:1, muted text 7.87:1, and rose accents on the provider surface 9.19:1. Functional borders measure 3.91:1 against provider surfaces and 4.35:1 against the panel. Focus indicators use the high contrast rose accent.

All 26 selected production browser cases passed across desktop and mobile. Coverage includes both routes at 11 portrait, landscape, and narrow viewport sizes, with and without OAuth callback errors; minimum control targets; provider request callbacks; keyboard order; retries; account mode switching; session redirects; and logout. New checks hold a provider request pending to verify both disabled controls, the busy state, and progress announcement, then audit the error state and open privacy dialog for WCAG AA violations with reduced motion. Shared sign in accessibility and immutable performance budgets also passed. An initial test selector matched Next's route announcer as well as the form alert; it was scoped to the main landmark before the final clean run.

Desktop, 375 pixel phone, short landscape, and legal dialog layouts were visually inspected. Enlarging the root text to 200 percent retained natural scrolling without horizontal overflow; this is a text enlargement check, not a claim of actual browser zoom coverage. The production build and TypeScript compilation passed. Validation used installed Node 26; supported Node 24 CI remains pending.
