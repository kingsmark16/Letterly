# Shared primitive state contrast and consumer coverage

The expanded existing contrast test passes in all six Chromium, Firefox, and WebKit profiles at 390 and 1440 CSS pixels. It measures four Button variants, Link, IconButton with a visible stroked glyph, Card, loading/empty/error/recovery Status content and visible cues, Field label/help/error text, empty and invalid text controls, Dialog title/description/close, and the five actual administration Inputs. Container and Stack do not introduce foreground or background colors; their inherited content and responsive geometry are covered by the existing fixture checks.

[The measurements](2026-10-05-shared-ui-state-contrast.json) contain 150 records, twenty five per profile, plus 84 enabled hover and pressed samples. Minimum normal text and visible graphic contrast are 5.40:1; minimum sampled interaction text is 7.95:1, focus 7.07:1, and required text control boundaries 5.27:1. Assertions retain 4.5:1 for normal text and 3:1 for focus, visible graphics, and required control boundaries. Disabled controls remain covered by behavior checks and exempt from contrast thresholds. This is measured evidence for these solid background compositions, not complete website WCAG certification.

The final targeted command passed 36 cases in 1.5 minutes, using the existing production fixture build and `playwright.ui.config.ts`, filtered to contrast, feedback, text controls, native dialog, layout primitives, and admin action buttons. The command used application origin `http://127.0.0.1:3103` and fixture API origin `http://127.0.0.1:3003`. An initial run passed 35 cases and failed one Chromium measurement on a cancelled CSS transition promise. The harness now polls until running or pending control animations settle, then samples computed colors. No threshold or assertion was removed. A subsequent six-profile contrast run passed in 46.7 seconds before the visible glyph and Status cue assertions were added.

The normal production build was restored and passed in 21.112 seconds with a fresh web build and cached API/database builds. Application source, tokens, package exports, routes, and contracts are unchanged by this milestone. The changes are in the existing test and its fixture only. Earlier performance comparisons therefore retain their production source scope; the new test fixture is excluded from production Tailwind scanning.
